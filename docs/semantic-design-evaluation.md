# 量子应用证据评审：语义方案探索与评估

日期：2026-10-18。状态：结构整理已完成；方向1离线原型停止；方向2、3尚未实现，未选定新的真实试验方案。

本文供未参与项目内部讨论的评审者评估设计。它给出问题定义、代表性证据、实际结果与待决问题，不要求读者访问内部回执。实验观察来自项目保存的响应和原文，由开发代理核对；不是第三方复现或真人抽查报告。

## 1. 要解决的问题

Quantum Scout 从论文等已打开来源抽取量子应用案例，经过原文定位、案例归属评审和语义评审，再进入应用类别准入及评分。

每个案例先检查八个字段：现实问题、参与方与角色、输入输出、约束、现有做法、量子机制作用、成功条件、部署边界。`FILLED` 表示运行系统已接受该字段的评审结果，**不保证语义正确**。归属评审判断证据是否属于目标案例，语义评审判断证据是否支持具体主张；两者职责不同，不能用其中一次替代另一次。

本次要解决的错误包括：已识别的限定没有进入结构化发现；所选原文片段未承载理由中的关键前提；理由加入了所选证据没有支持的解释。原文定位成功、输出格式正确和消费端显示一致，都不足以排除这些错误。

调度统一、占用事实归一、诊断退出调度、人工单选回写等结构工作已完成离线验证。它们解决运行一致性，不构成语义有效性的验证。集合结论尚未实现；人工身份字段为调用方声明，不构成身份认证。这些不是本次语义探索要扩展的功能。

## 2. 实际证据与适用范围

第37–39次单案例运行使用同一DIQKD研究背景：Nadlinger等人的 [Experimental quantum key distribution certified by Bell’s theorem，arXiv:2109.14600v2](https://arxiv.org/abs/2109.14600v2)。论文是物理与协议陈述的来源；以下模型响应和系统失败属于项目自己的实验观察，不能归因于论文。

第39次运行实际进行了16次模型调用，耗时123.58秒；已知用量143,028 tokens，其中15次响应有用量，最后一次中断用量未知，美元费用未知。结果为八字段中6个原生FILLED，但语义验收失败，未进入准入或评分；执行代理按约定止损，未自动续跑。本轮探索仅重读保存材料，新增模型调用和付费均为0。

| 运行及字段 | 原文与输出的直接对照 | 能成立的判断 |
|---|---|---|
| 37：约束、量子机制、参与方 | 原文有私有随机输入、可信计算机和不依赖对手算力限制等条件；部分所选片段分别遗漏“私有”“可信”或否定关系，理由却引用这些含义。 | 所选证据不足以承载理由；原文其他位置存在条件不能替代当前所选证据。 |
| 38：部署边界 | 原文说明测量没有类空分离；模型总结承认这一点，但结构化发现列表为空。 | 与候选相容或已被候选写出的限定，仍可能被发现列表遗漏。 |
| 38：成功条件 | 原文报告密钥长度比消耗的私有共享随机量大两个数量级以上；候选仅说前者大于后者。模型把相关发现放入矛盾列表，理由却写了“No direct contradiction found”。 | 更强结果不与较弱的不等式自动矛盾；该次分类与其理由不一致。 |
| 39：输入输出 | 原文区分Bell测试轮的随机输入与密钥轮的固定输入。模型总结明确写出“While key generation rounds use fixed settings (Xi=0, Yi=2)”，四类发现列表仍全空。 | 限定保留失败，不必先把候选解释为“所有轮次都随机”。 |
| 39：现有做法 | 原文说明既有QKD依赖设备表征，测量设备无关QKD仍要求来源表征。模型总结承认这些要求，发现列表仍全空。 | 与候选一致的安全假设也发生了遗漏。 |
| 39：成功条件 | 所选片段Q123从“it not the case”开始，理由却断言它明确包含CHSH阈值条件；Q124用“Otherwise”承接前文。阈值命题在更早位置。 | 所选证据依赖未绑定的前件。完整句或更长片段不自动等于完整论据。 |
| 39：约束 | Q41说明DIQKD不增加关于物理设备的假设。模型理由据此称关闭探测漏洞是“an experimental requirement for *this specific implementation*”。 | Q41本身不足以支持这一区分；这不是对整篇论文不存在其他支持的断言。 |

Q123、Q124、Q41是该次请求中的局部证据编号，不是论文正式编号。保存文本中，CHSH阈值句起点为10,475，Q123起点为13,265，相距2,790个字符。该数值只说明当前文本的跨片段依赖，不是token数、最佳窗口长度或普遍裁剪规则。

第39次没有直接触发“数值强弱关系误判矛盾”的目标，不能据此判断该判据有效或无效。现实问题字段未通过归属评审，部署边界的语义响应中断，二者均不补写语义结论。现有观察也不证明模型过载、内部意图或某种架构必然失败。

## 3. 方向1：共用发现表示的原型与停止原因

假设是：解释与导出共用一份原文绑定的发现列表，可减少重复生成解释时的不一致。硬约束是：**消费端共用，验收端仍独立对照原文**。消费端一致不能成为语义验收的唯一依据。

隔离原型回放了第37–39次的20份已完成语义评审，检查11个已知失败点及2个局部对照。原型没有进入线上链路，没有改变证据规则、调度接口或人工汇总契约。

| 指标 | 审阅后的实际结果 | 含义 |
|---|---|---|
| 结构化发现列表差异 | 原型前0，原型后0 | 历史结构化列表本来已一致，没有可宣称的下降。 |
| 限定列表差异 | 原型前0，原型后0 | 同上，不代表限定完整。 |
| 旧总结与列表的已标注分歧 | 4处：3处遗漏、1处分类分歧；原始材料仍保留这4处 | 新解释不再独立生成总结，因此没有同口径的“原型后”数值。 |
| 已知失败回放 | 10项固定片段／分类检查命中；1项仅保留旧标注 | 不能称为11项均经独立语义检查捕获。 |
| 局部对照 | 2项无缺口 | 排除“一律报错”的部分情形，不证明一般正确性。 |
| 调用与成本 | 新增模型调用0，新增付费0 | 仅离线回放。 |

关键缺陷在Q41：检查代码验证了原文哈希、片段位置及旧理由匹配，然后直接返回“捕获”。它证明的是旧审阅标注没有丢失，**没有重新比较该理由与原文之间的支持关系**。

因此撤回最初的“11/11独立捕获”表述。最初的“4→0”也被撤回，因为它把旧总结分歧数与新消费端列表差异数混为一谈。修正后原型按反掩盖条件返回失败并停止。10项报告与停止行为检查通过，只证明失败被如实报告，不代表原型验收通过。

此次停止否定的是这份原型的验收证明，不证明“共用发现表示”在所有设计中都无价值。独立验收也不必天然是自动程序：实际原文审阅可以由人或明确标识的代理承担；但不能将预存的正确答案回放成一次新审阅，也不能把代理审阅称为真人抽查。

## 4. 方向2：分离锚点选择与支持判断

该方向尚未实现。需区分以下几种含义，否则“分离”容易只是换一种输出格式。

| 设计变体 | 可直接处理的问题 | 尚未解决的问题与代价 |
|---|---|---|
| 同一次响应中分别列锚点与支持判断 | 使两者关系更便于检查 | 仍由同一次生成完成；不能因此声称独立验收，更不能证明会发现空列表中遗漏的条件。 |
| 显式绑定多个原文片段，再判断支持关系 | 可以表示Q123/Q124与较早阈值句的依赖，避免让单个片段承担它未包含的前提 | 只是表示能力的候选改进。片段选择、限定是否完整、Q41理由是否越界仍需要语义判断；不应通过拼接伪造连续原文。 |
| 一次选择／发现调用，再一次独立支持评审 | 将发现结果固定为后一阶段的审阅对象，形成不同于同次输出自洽的流程 | 增加调用；后一阶段仍可能接受错误，且若只读前一阶段选出的片段，会继承遗漏。必须另有独立原文验收，不能靠两次判断一致证明正确。 |
| 把选择任务移入已有抽取调用，保留归属和语义评审 | 可能保持调用数量 | 当前抽取本来就选择候选证据。需要说明新增结构与现有流程的实质差别，以及抽取偏差如何不被下游继承；当前没有这方面的有效性证据。 |

历史分步链路在第25次运行中也曾接受丢失否定的短引。因此，新增一个“保真”或“支持”阶段本身不是已被证明的修复。

**可行性结论：** 多片段绑定针对证据承载有具体动机，但方向2目前没有同时解决限定遗漏与理由越界的已验证机制，也没有新的独立语义验收结果。不应仅为展示流程能串起来而实施下一份原型，或把旧标注再次当作验收器。

调用成本可先按职责估算：若一个来源产生八个候选，全部经过归属与语义评审，忽略重试、后续来源、准入和评分，则是1次抽取＋8次归属＋8次语义＝17次。若每个候选再增加一次独立选择／支持调用，同一路径为25次，增加8次，约47%。这是结构计数示例，不是实际运行预测、token估计或费用上限；第39次实际为16次，不能直接套用25次作为下一笔预算。

本轮0新增调用不等于永久禁止未来增调用。若考虑真正分步方案，必须先明确新增职责、输入规模、独立验收者、价格及逐笔上限，再另行授权；不能借“离线方案通过”默认为已获预算。

## 5. 方向3与下一项决策

方向3是缩小评审范围。目前没有证据证明过大的输入是已确认错误的原因：模型已经在总结中提到相关限定，却仍遗漏结构化发现。跨片段前件也表明直接裁剪可能删除必要证据。因此方向3暂不实施；若重新考虑，先证明原文支持与反证范围未被截断，不把输入变短当作语义改进。

下一项决策应是**谁在未来试验中实际进行独立原文验收，以及该验收覆盖什么范围**，而不是直接选择另一个结构名字。评审者可据以下问题判断是否值得继续：

1. 是否接受由明确标识的人工或代理对新输出逐条核对原文，而不是要求离线代码自动判断所有语义问题？若要求自动判断，本轮并未提供这样的组件。
2. 若采用方向2，两阶段的职责与原文访问范围有何实质区别？怎样防止后续评审仅复述上游遗漏？独立验收不能只检查两阶段是否一致。
3. 新设计应明确承诺解决哪类错误，以及未解决部分如何仍被验收发现；不能把可表示跨片段证据写成已解决限定遗漏或理由越界。
4. 若需要新增调用，是否接受其具体成本？正式试验须固定新基线、新工作目录与预算，重新抽取及双审；任一已完成响应语义验收失败即停，不纠错续跑、不继承旧额度。

当前没有获准的新真实运行。结构性收尾仍成立；真实结果仍为第39次6/8 FILLED、语义验收失败、未准入／评分。
