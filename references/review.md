# 阶段复盘

> 本文件唯一维护：阶段人工复盘和后续批次决策。跨职责规则通过链接引用其权威文档。

阶段结束或用户要求时复盘；pilot、expand 通过且用户明确确认才更新 current_phase。production 模式转换也必须单独确认。每阶段抽查 ceil(本阶段纳入案例数 × 10%)，非零阶段至少一条；记录抽样方法、样本 case_id、核对者及时间。人工未核对的内容标 pending，模型自检不能冒充人工完成。

复盘文件包含：假阳性、假阴性、引用真实性、数值/单位/换算准确性、评分阈值、搜索策略更新、下一阶段决定。

- 假阳性分母为复核的纳入案例；假阴性分母为本阶段 `excluded_cases` 中按拒绝原因分层抽取、并经人工复核的候选数；每个存在的拒绝原因尽量抽取至少 3 条，少于 3 条时全量抽取。分子为其中经人工复核确认应纳入、但被漏掉的案例数。没有已判定样本/分母时，报告为字面量 `unknown`，不得报告为 0%（0% 会被误认为真实测量值）。
- 证据不一致率 = 不真实或错引证据项/已复核证据项。
- 定量不一致率 = 不一致的非空指标/已复核非空指标。复核每个选中案例的全部指标；没有指标则 N/A。
- 误报 >20% 或漏报 >30% 必须调整配置并重跑受影响批次；这些阈值当前硬编码于本规范，如需调整必须同步更新本文档和复盘记录。保留旧配置、批次与变更理由，不抹去原日志。
- 证据或定量不一致率 >5% 暂停，查清机制失效原因，修复并重新复核后再申请阶段确认。

复盘未完成、分母未知或人工核对 pending 时不宣布复盘通过。生产库通过 search_log 的 review 事件保留决定、用户明确确认原文或会话标识、阈值与配置版本。calibration 同结构保存在本批 JSON。若用户已在会话明确确认转换，不重复询问，但不能把不合格数据包装成合格。

维护说明：SQLite 支持范围/JOIN；直接列存支持常用筛选，provenance JSON 保存字段证据，Markdown 方便人审；默认校准避免污染主库，批次早发现漂移。严格证明、无需容错和 Bell 非局域性边界优先于案例数量。

复盘还必须抽查问题定义完整性：核对 8 个字段、逐字段引文与现实问题判定；缺失字段不得被写成完整定义。


## 证据不足归因

当 `insufficient_evidence_admission_ratio` 高于零时，必须按以下三类归因并报告计数与比例：

- `metadata_only`：本次只读摘要、索引或元数据；应检查来源状态是否为 `opened_metadata_only`。
- `missing_in_document`：已读取正文，但文献没有给出该准入项。
- `semantic_ambiguity`：正文存在，但语义无法稳定映射到准入条件。

该归因只用于复盘，不能回写准入结果或放宽规则。若 `metadata_only` 占比超过 50%，下一批必须复核来源打开层级。复盘还应核对每个 checkpoint 的 `input_source_ids` 是否只含本批正文来源，以及 checkpoint 是否仅保存本批 `new_source_ids`、`counts_delta` 和增量事件；累计来源、案例和完整证据只应出现在最终 batch JSON。复盘还应核对操作性停止的 stop_evidence、未解决字段和 grounding_failures；历史 discovery_pool_exhausted 只作未验证声明审计，不认可全局耗尽。

模型输出在入图前的契约拒绝（operational_cause=contract_violation）单独审计与统计，
不纳入“已复核证据/定量不一致率”的分子或分母，也不据此判定系统故障。本文没有 error 停止占比 5% 的规则。
系统性输出违规仍需校准模型或提示词；已经入图的证据若经复核发现错误，仍适用原 5% 暂停规则。

上述已复核分母指人工已复核样本：仅通过自动双复核入图但未人工抽查的项不计入。契约拒绝消耗的调用仍计入成本。


## 定期分支调查

每 10 个独立 workspace 的最新批次快照执行一次只读观察：
`python scripts/audit_reachability.py <workspace...> --window 10 --output <validation/branches.json>`。
工具按停止值、警告类别和字段缺口原因记录出现情况；不足窗口保留 insufficient_window。
连续窗口未观察到的项只标 investigate_reachability：核对适用条件、单元测试及调度可达性，
不推断死代码，不自动删除。最新 workspace 快照不是每次 invocation 的历史警告轨迹。
构造测试可检验代码边界，必须与真实模型行为、真实人工审计和 production 写库测试分开报告。
